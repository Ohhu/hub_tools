# 开发指南

`LinuxDo Hub Tool.user.js` 是安装到 Tampermonkey / 油猴的最终单文件**产物**。日常开发修改 `src/` 下的**源码片段**，再重新构建。用词遵循[术语表](../参考/术语表.md)。

## 常用命令

| 目的 | 命令 |
| --- | --- |
| 构建产物 | `node scripts/build-userscript.js` |
| 检查产物与源码同步 | `node scripts/check-userscript.js` |
| 运行全部测试 | `node --test tests/*.test.js` |
| 语法检查产物 | `node --check "LinuxDo Hub Tool.user.js"` |
| 语法检查构建脚本 | `node --check scripts/build-userscript.js && node --check scripts/check-userscript.js` |

helper 级回归测试也可单独运行：

```bash
node tests/minimal-binder.test.js
node tests/request-utils.test.js
node tests/profile-binding.test.js
node tests/marketplace-pricing.test.js
```

## 开发约定

- 优先修改 `src/`，不要直接手改根目录产物。
- 修改后运行 `node scripts/build-userscript.js` 更新 `LinuxDo Hub Tool.user.js`。
- 提交前运行同步检查和测试，避免源码与产物不一致。
- `scripts/build-userscript.js` 中的 `SOURCE_FILES` 是零依赖构建的模块边界，新增源码片段必须按层级插入。

## 源码层级顺序

`SOURCE_FILES` 的顺序就是运行时依赖顺序（当前为 9 个功能域文件）：

1. `src/userscript-header.js` — 油猴 metadata 头
2. `src/base.js` — 常量、全局状态、请求体/URL 工具
3. `src/graphql.js` — GraphQL 查询、统一请求 client 和 pricing query 改写
4. `src/marketplace-pricing.js` 与 `src/marketplace-payload.js` — 市场价格判断、免费谓词、缓存、分页扫描与 payload 转换
5. `src/fetch-patch.js` — 全局请求拦截与响应包装
6. `src/channel-cache.js` — 渠道缓存、payload 渠道提取与 React 探测
7. `src/page-integration.js` — 选择器、路由挂载和页面 UI 集成
8. `src/api-keys.js` — 密钥服务、配置绑定与弹窗 UI
9. `src/bootstrap-and-test-exports.js` — 启动和测试导出，必须保持最后

## 重构约定

- 优先抽纯函数和测试，再移动 DOM / UI 逻辑。
- 不在同一轮同时改变行为和移动大段代码。
- 涉及 `window.fetch`、history patch、MutationObserver、React Fiber 探测时保持小步修改。

## 未来 ESM / esbuild 迁移路径

当前保持零依赖 userscript 拼接构建。迁移到 ESM / esbuild 前应先完成以下准备，避免一次性改变构建方式和运行行为：

1. 继续把大文件拆成稳定的小边界文件，每次移动只改变文件位置，不改变行为。
2. 为新边界补充 helper 级测试或 bundle smoke 测试，先锁定现有全局函数行为。
3. 在源码中逐步形成清晰的依赖方向：`base` → `graphql` → marketplace（pricing / payload）→ `fetch-patch` → `channel-cache` → `page-integration` → `api-keys` → bootstrap。
4. 引入 ESM 时先保留现有 `scripts/build-userscript.js` 作为基准构建，再新增并行的 bundler 构建脚本。
5. bundler 输出必须继续包含 userscript metadata header，且生成的单文件应通过 `node --check`、现有测试和 bundle smoke 测试。
6. 在 bundler 输出与当前拼接输出的关键运行行为一致前，不替换发布产物构建路径。

**最小切换点**：当主要源码边界都能用显式 import/export 表达，且并行 bundler 输出通过完整测试后，再把发布构建从拼接脚本切到 esbuild。
