## 步骤 3：GetChannelModelProbeData

```graphql
query GetChannelModelProbeData($input: GetChannelModelProbeDataInput!) {
  channelModelProbeData(input: $input) {
    channelID
    modelID
    points { timestamp totalRequestCount successRequestCount avgTokensPerSecond avgTimeToFirstTokenMs }
  }
}
```

variables 的 `input.items` 是全部 351 个 `{channelID, modelID}` 组合，一次性批量请求。

## 要点

- provider 的 `channel` **内联 `channelModelPrices`**，但**没有** `priceSummary`——与渠道广场列表正好互补，是价格筛选设计中两套判定路径的依据（见[价格筛选设计](../设计/价格筛选.md)第 4.2 节）。
- 页面原始 query 的 `pricing` 只选 `usagePerUnit`，**不含 `mode` / `flatFee`**——这正是脚本要拦截补字段的原因：仅凭 `usagePerUnit: 0` 无法区分「免费」和「flat_fee 计费」。
- `healthStats` 样本不足时（`sampleSufficient: false`）`successRate` 等字段为 `null`，消费方需判空。
- `channelModelPrices` 会包含该渠道**所有**有价模型（如同时含 `gpt-5.4` / `gpt-5.3-codex` 的价格行），不只是当前模型。
