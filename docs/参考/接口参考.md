## 1. 站点结构

### 1.1 页面路由


| 路由                                     | 页面          | 说明                        |
| -------------------------------------- | ----------- | ------------------------- |
| `/`                                    | 仪表板         | 请求数、成功率、词元统计、每日概览         |
| `/channels`                            | 我的渠道        | 渠道管理                      |
| `/marketplace`                         | 资源市场        | 三个 Tab：模型广场 / 候选搜索 / 渠道广场 |
| `/marketplace/models/:modelID`         | 模型详情页       | 模型的渠道列表与定价                |
| `/marketplace/reports`                 | 我的举报        |                           |
| `/project/api-keys`                    | 密钥页         | 密钥管理与配置绑定                 |
| `/project/requests?view=consumer`      | 请求          | 我发起的调用记录                  |
| `/project/requests?view=provider`      | 渠道被调用记录     |                           |
| `/project/playground`                  | 测试场         |                           |
| `/project/threads` / `/project/traces` | 线程 / 追踪     |                           |
| `/wallet`                              | 钱包          | 市场结算余额                    |
| `/settings/profile` / `/project/users` | 个人资料 / 项目成员 |                           |
| `/release-notes`                       | 更新日志        |                           |




### 1.2 认证与请求上下文

- 前端把 JWT 存在 `localStorage.axonhub_access_token`，请求头携带 `authorization: Bearer <token>`。
- 项目上下文通过 `x-project-id` 头传递，值来自 `localStorage.axonhub_selected_project_id`（如 `gid://axonhub/Project/1`）。
- 其他有用的 localStorage 键：`axonhub_user_info`（用户 JSON）、`i18nextLng`、`marketplace.channels.viewMode`。
- 全站 ID 采用 GID 形式：`gid://axonhub/<Type>/<数字>`，如 `gid://axonhub/Channel/2223`。
- 每个响应带 `ah-request-id` 头，可用于问题排查。

### 3.3 核心类型

字段格式 `name: Type!`（`!` 为非空）。仅列脚本关心的类型，完整定义可 introspection。

#### APIKey / Profile

> `key` **字段隐私规则（2026-09-04 实测）**：无论 apiKeys 列表查询还是 node(id:) 单查询，`key` 明文只有在 selection 同时包含 `user { id }` 时才返回；否则被服务端 privacy 规则抹为空串且不报错。禁用状态的 Key 同样可取回明文。列表 UI 的 `****a93f` 是前端掩码，非服务端返回。

```graphql
type APIKey {
  id: ID!  createdAt: Time!  updatedAt: Time!
  userID: ID  projectID: ID!
  key: String!  name: String!
  type: APIKeyType!          # user | service_account | noauth
  status: APIKeyStatus!      # enabled | disabled | archived
  scopes: [String!]          # 如 read_channels / write_requests
  profiles: APIKeyProfiles
  user: User  project: Project!
}

type APIKeyProfiles { activeProfile: String!  profiles: [APIKeyProfile!] }

type APIKeyProfile {
  name: String!
  modelMappings: [ModelMapping!]     # { from, to }
  channelIDs: [Int!]                 # 注意：数字 ID，不是 GID
  channelTags: [String!]
  channelTagsMatchMode: ChannelTagsMatchMode   # any | all | none
  modelIDs: [String!]
  quota: APIKeyQuota                 # { requests, totalTokens, cost, period }
  loadBalanceStrategy: String
  routingPolicy: APIKeyRoutingPolicy
  channelBindingMode: ChannelBindingMode       # manual | dynamic
  dynamicChannelStrategy: DynamicChannelStrategy
}

type DynamicChannelStrategy {
  mode: DynamicStrategyMode!   # price_first | quality_first | balanced | official_only | high_availability | detection_first
  selectionPolicy: DynamicSelectionPolicy      # ranked | sticky_hrw | power_of_two
  maxChannels: Int  minChannels: Int
  maxPriceMultiplier: Float  maxLatencyMs: Int  minSuccessRate: Float
  onlyOfficial: Boolean
  includeTags: [String!]  excludeTags: [String!]
  excludeChannelIDs: [Int!]  fallbackChannelIDs: [Int!]
}
```

`APIKeyQuota.period.type`：`all_time | past_duration | calendar_duration`。

**profiles 输入类型（2026-09-05 内省实测）**：字段与上面输出类型同名，把读到的 `profiles` 剔除 null 与必填字段缺失的节点后即可原样回写（脚本轮换密钥即用此法完整迁移配置）：

```graphql
input UpdateAPIKeyProfilesInput { activeProfile: String!  profiles: [APIKeyProfileInput!] }

input APIKeyProfileInput {
  name: String!
  modelMappings: [ModelMappingInput!]                  # { from, to }（均必填）
  channelIDs: [Int!]
  channelTags: [String!]
  channelTagsMatchMode: ChannelTagsMatchMode
  modelIDs: [String!]
  quota: APIKeyQuotaInput                              # period.type 必填
  loadBalanceStrategy: String
  routingPolicy: APIKeyRoutingPolicyInput
  channelBindingMode: ChannelBindingMode
  dynamicChannelStrategy: DynamicChannelStrategyInput  # mode 必填
}

input DynamicChannelStrategyInput {
  mode: DynamicStrategyMode!  selectionPolicy: DynamicSelectionPolicy   # ranked | sticky_hrw | power_of_two
  maxChannels: Int  minChannels: Int  maxPriceMultiplier: Float  maxLatencyMs: Int
  minSuccessRate: Float  minCacheRate: Float  minDetectionScore: Float  onlyOfficial: Boolean
  includeTags: [String!]  excludeTags: [String!]  excludeChannelIDs: [Int!]  fallbackChannelIDs: [Int!]
}

input APIKeyQuotaInput { requests: Int  totalTokens: Int  cost: DecimalInput  period: APIKeyQuotaPeriodInput! }
input APIKeyQuotaPeriodInput {
  type: APIKeyQuotaPeriodType!
  pastDuration: APIKeyQuotaPastDurationInput           # { value: Int!, unit: enum }
  calendarDuration: APIKeyQuotaCalendarDurationInput   # { unit: enum }
}

input APIKeyRoutingPolicyInput {
  channelWeights: [ChannelWeightInput!]        # { channelID: Int!, weight: Float! }
  providerWeights: [ProviderWeightInput!]      # { provider: String!, weight: Float! }
  includeProviders: [String!]  excludeProviders: [String!]
  allowChannelAPIKeys: [ChannelAPIKeyRestrictionInput!]   # { channelID: Int!, keyHashes: [String!]! }
  excludeChannelAPIKeys: [ChannelAPIKeyRestrictionInput!]
  fallbackChannelIDs: [Int!]  excludeChannelIDs: [Int!]
}
```

**多 profile 复制语义（上游** `internal/server/biz/api_key.go` **实证）**：`updateAPIKeyProfiles` 对 profiles 做**整体替换**（`SetProfiles(&profiles)`），非合并。校验约束：

- profile `name` 唯一（不区分大小写）、非空；
- `activeProfile` 必须存在于 profiles 列表（精确匹配，区分大小写）；
- `quota` 若提交则 requests/totalTokens/cost 至少一项且为正数；
- 被复制的源 Key 配置天然满足上述校验（服务端写入时已验证过），读取 → 剔除 null → 回写即完整迁移。

因此「双配置 Key（default + Auto、activeProfile=Auto）更新密钥」= 把读到的全部 profiles 原样回写给新 Key，`activeProfile` 一并带回。

请求页两个视图的实测结构（2026-09）：

- 「请求」（consumer）与「渠道被调用记录」（provider）共用同一张请求表格组件；列的显示由**权限**决定（渠道列需 `canViewChannels` 或 `canViewDetails`，API 密钥列需 `canViewApiKeys` 或 `canViewDetails`），与视图无关。有权限用户访问无 `view` 参数的 `/project/requests` 时默认渲染「全部调用记录」（all）视图。
- 视图差异只影响请求列表的过滤范围，通过 `X-Request-View` 请求头与 URL `?view=` 参数区分；行按请求 ID 键控，切换视图时表格整体换行，但表头 DOM 会被 React 复用（外部注入的节点不会被 React 清除，需要注入方自行清理）。
- 每行带 `usageLogs(first: 1)` → `costExplanation.lines[].multiplier`，该倍率是站点按「渠道实际单价 ÷ 官方单价」推算的参考值（页面文案：仅供参考）。列头文案走 i18n（渠道列 zh「渠道」/ en「Channel」）。



## 4. 市场结算规则（页面公示）

- 调用其他用户的公开渠道从调用方钱包扣费，同等金额入账渠道所有者。
- 使用自己创建的渠道不产生扣费或收入。
- 只有配置了模型定价的渠道才会结算，否则请求免费。
- 可用余额不足以覆盖预估费用时，请求执行前直接拒绝。
