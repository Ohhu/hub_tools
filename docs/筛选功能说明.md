# 筛选功能说明

本文记录 `LinuxDo Hub Tool.user.js` 中价格筛选相关的实现逻辑、使用的接口，以及关键数据结构。

## 功能范围

脚本在 Linux.do Hub Marketplace 页面增加价格筛选入口。当前 UI 是一个“免费”切换按钮：

- 未选中 `免费`：视为 `全部`，不改写列表数据。
- 选中 `免费`：只展示判定为免费的渠道。

代码中仍保留 `paid` 模式的判定分支，但当前页面没有暴露“付费”按钮。

当前版本的筛选状态保存在脚本内存变量 `selectedPriceFilter` 中，不再通过 URL 参数保存。旧版本遗留的 `price` 参数会被清理：

```text
?price=free
?price=paid
```

因此刷新页面或路由重建后，筛选状态可能回到默认 `all`。

## 页面与数据源

### Channel Hub 列表

接口：

```text
GET /admin/marketplace/channels
```

常见查询参数：

```text
page=1
first=20
search=gpt-5.5
tag=all
sort=multiplier_asc
```

响应核心结构：

```json
{
  "items": [
    {
      "id": "gid://axonhub/Channel/6713",
      "name": "GPT5.5",
      "supportedModels": ["gpt-5.5"],
      "priceSummary": {
        "allFree": true,
        "hasPrices": false
      }
    }
  ],
  "totalCount": 353,
  "totalPages": 18,
  "page": 1
}
```

Channel Hub 的免费判断优先使用后端返回的渠道级字段：

```js
channel.priceSummary.allFree === true
```

当搜索框存在模型关键词时，`priceSummary.allFree` 只能表示渠道整体是否全免费，不能表示当前搜索命中的模型是否免费。脚本会结合 `supportedModels` 找到匹配搜索词的模型；如果渠道有显式定价，则额外补拉该渠道的模型价格明细后再判断当前匹配模型是否免费。

筛选过程在脚本侧完成。脚本代理目标接口的 `response.json()`，读取原始 payload 后过滤 `items`，再返回新的 payload 给页面渲染。

免费筛选时，脚本请求后续页会使用 `sort=multiplier_asc`，以便免费/低价渠道尽量靠前。

扫描停止条件分两种情况：

- 无搜索词时：如果当前页已经出现 `priceSummary.allFree === false` 的项，会提前停止继续翻页，减少请求量。
- 有搜索词时：不会因为出现非全免费渠道而提前停止。因为此时需要判断“搜索命中的具体模型”是否隐式免费，后续页仍可能存在满足条件的渠道。

### 模型详情页

接口：

```text
POST /admin/graphql
```

操作名：

```text
MarketplaceModel
```

请求核心结构：

```graphql
query MarketplaceModel($modelID: String!, $window: HealthWindow) {
  marketplaceModel(modelID: $modelID) {
    modelID
    providers {
      modelID
      channel {
        id
        name
        supportedModels
        channelModelPrices {
          modelID
          price {
            items {
              itemCode
              multiplier
              pricing {
                mode
                flatFee
                usagePerUnit
              }
            }
          }
        }
      }
    }
  }
}
```

页面原始 query 可能只请求 `pricing.usagePerUnit`。脚本会在拦截 `MarketplaceModel` 请求时补充：

```graphql
pricing {
  mode
  flatFee
  usagePerUnit
}
```

原因：模型详情页价格表中的固定费用来自 `pricing.flatFee`。如果不请求该字段，像下面这种渠道会被误判为免费：

```json
{
  "modelID": "cat/gpt-5.5",
  "price": {
    "items": [
      {
        "itemCode": "prompt_tokens",
        "multiplier": 20,
        "pricing": {
          "mode": "flat_fee",
          "flatFee": 100,
          "usagePerUnit": 0
        }
      }
    ]
  }
}
```

这里页面展示的 `输入 (USD) = 100` 对应 `flatFee: 100`，不是 `multiplier: 20`。

## 免费判定规则

### Channel Hub

无搜索词时，使用后端聚合字段：

```js
typeof channel.priceSummary.allFree === "boolean"
```

- `true`：免费。
- `false`：付费。
- 缺失：未知，不进入免费/付费结果。

有搜索词时，免费判断进入模型粒度：

1. 使用搜索词匹配 `channel.supportedModels`。
2. 如果没有匹配模型，退回渠道级 `priceSummary.allFree`。
3. 如果匹配模型存在，且 `priceSummary.hasPrices === false`，认为匹配模型免费。
4. 如果匹配模型存在，且 `priceSummary.hasPrices === true`，补拉 `ChannelModelPrices`。
5. 在补拉结果中查找匹配模型的价格行：
   - 有显式价格行：按 `modelPriceItemsFree(...)` 判断。
   - 没有显式价格行：按隐式免费处理。

补拉查询：

```graphql
query ChannelModelPrices($id: ID!) {
  node(id: $id) {
    ... on Channel {
      id
      channelModelPrices {
        id
        modelID
        price {
          items {
            itemCode
            multiplier
            pricing {
              mode
              flatFee
              usagePerUnit
              usageTiered {
                tiers {
                  upTo
                  pricePerUnit
                }
              }
            }
            promptWriteCacheVariants {
              variantCode
              pricing {
                mode
                flatFee
                usagePerUnit
              }
            }
          }
        }
      }
    }
  }
}
```

### 模型详情页

`marketplaceModel.providers` 已经是当前模型详情页的渠道集合，因此脚本不再额外判断渠道是否支持当前模型。

模型详情页没有稳定的 `priceSummary` 字段时，脚本使用渠道价格明细判断：

```js
channel.channelModelPrices[].price.items[].pricing
```

当前实现不是简单地“没有正数就免费”，而是按 `pricing.mode` 选择对应字段：

```js
flat_fee       -> pricing.flatFee
usage_per_unit -> pricing.usagePerUnit
usage_tiered   -> pricing.usageTiered.tiers[].pricePerUnit
```

判定规则可以理解为：

- `flat_fee`：`flatFee <= 0` 才免费。
- `usage_per_unit`：`usagePerUnit <= 0` 才免费。
- `usage_tiered`：必须存在 tiers，且所有 `pricePerUnit <= 0` 才免费。
- 如果响应里携带 `promptWriteCacheVariants`，所有缓存写入变体的价格也必须免费。
- 空价格项、无法解析的价格、未知或不完整的价格结构不会直接按免费处理。

`item.multiplier` 不单独作为收费依据。它是倍率展示/换算信息，不等同于最终价格；实际页面展示的固定价格来自 `pricing.flatFee`。

### MCP 实测的数据差异

2026-06-21 使用浏览器 MCP 对比了两个页面实际携带的数据，结论是两个地方的数据结构不同。

渠道广场搜索 `gpt-5.4` 时，请求：

```text
GET /admin/marketplace/channels?page=1&first=20&search=gpt-5.4&tag=all&sort=balanced
```

响应 item 携带：

- `priceSummary`
- `supportedModels`

但不携带：

- `channelModelPrices`

MCP 摘要：

```json
{
  "itemCount": 20,
  "fieldStats": {
    "withPriceSummary": 20,
    "withSupportedModels": 20,
    "withChannelModelPrices": 0,
    "hasPricesTrue": 10,
    "allFreeTrue": 10,
    "allFreeFalse": 10
  }
}
```

主动补拉会尽量复用当前 Marketplace 请求上下文。脚本会记住 `/admin/*` 请求中的 `authorization` 和 `x-project-id`，补拉 `ChannelModelPrices` 时优先使用当前请求的 headers；当前请求缺失时，再使用已记住的上下文。

其中一个需要补拉的渠道示例：

```json
{
  "id": "gid://axonhub/Channel/5074",
  "name": "【低价】0.01倍 低价国模 不限量",
  "priceSummary": {
    "allFree": false,
    "hasPrices": true
  },
  "supportedModelsCount": 247,
  "matchedModels": ["gpt-5.4", "gpt-5.4-mini"],
  "hasInlineChannelModelPrices": false
}
```

此时仅凭 `priceSummary.allFree === false` 只能说明该渠道整体不是全免费，不能说明搜索命中的 `gpt-5.4` 一定收费。因此脚本必须补拉模型价格行。

对该渠道补拉 `ChannelModelPrices` 后，MCP 摘要：

```json
{
  "fetchedRows": 123,
  "matchedRows": [
    {
      "modelID": "gpt-5.4",
      "hasExplicitRow": true,
      "freeByRowsRule": false
    },
    {
      "modelID": "gpt-5.4-mini",
      "hasExplicitRow": true,
      "freeByRowsRule": false
    }
  ]
}
```

模型详情页 `https://hub.linux.do/marketplace/models/gpt-5.4` 则请求 GraphQL `MarketplaceModel`。MCP 摘要：

```json
{
  "modelID": "gpt-5.4",
  "providersCount": 353,
  "providerStats": {
    "withChannel": 353,
    "withPriceSummary": 0,
    "withSupportedModels": 0,
    "withChannelModelPrices": 353
  }
}
```

也就是说，模型详情页 provider 的 `channel` 已经内联了 `channelModelPrices`，但没有 `priceSummary` 和 `supportedModels`。模型详情页通常可以直接用内联价格明细判断当前模型是否免费，不需要像渠道广场搜索那样先通过 `supportedModels` 找匹配模型再补拉明细。

### 隐式免费与模型定价页

当前规则中，匹配模型没有显式价格行时按隐式免费处理：

```js
function modelFreeInPriceRows(modelID, prices) {
  const row = findModelPriceRow(prices, modelID);
  return row ? modelPriceItemsFree(row?.price?.items) : true;
}
```

这条规则用于解决一种常见情况：渠道有一些模型设置了显式价格，但并非所有 `supportedModels` 都有独立价格行；没有独立价格行的模型按免费或默认无额外费用处理。

为了避免“筛选认为免费，但模型定价页看不到该模型价格行”的体验不一致，脚本在拦截 `ChannelModelPrices` 响应时，会为当前渠道广场搜索命中的隐式免费模型补充临时的 0 价格行：

```text
id: implicit-free:<channelID>:<modelID>
price.items:
  - prompt_tokens: usage_per_unit 0
  - completion_tokens: usage_per_unit 0
```

这类行只存在于脚本返回给页面的响应中，不会写回后端。

当前嵌入逻辑的触发条件应保持收敛：

- 必须存在渠道广场搜索词。
- 必须能从缓存中找到对应渠道。
- 渠道必须 `priceSummary.hasPrices === true`。
- 搜索词必须能匹配该渠道的 `supportedModels`。
- 匹配模型在真实 `channelModelPrices` 中不存在显式价格行。

这样做的目的是只补齐“搜索免费判断已经依赖的隐式免费模型”，避免把一个渠道支持的全部模型都注入定价页，导致列表过长或误导用户。

模型详情页的 `MarketplaceModel` 已经携带当前模型的 `channelModelPrices`。如果某个 provider 的当前模型没有显式价格行，脚本可以按同样的隐式免费规则判断为免费；但是否也要在模型详情页的定价展示中注入临时 0 价格行，需要单独权衡：

- 优点：筛选结果和定价展示完全一致，用户能看到“当前模型免费”的显式证据。
- 缺点：模型详情页没有 `supportedModels` 和 `priceSummary`，上下文比渠道广场搜索少；如果无条件注入，可能把“缺失价格明细”误展示成“明确免费”。

因此目前更安全的策略是：渠道广场搜索场景可以基于 `supportedModels + priceSummary + ChannelModelPrices` 三者交叉验证后注入隐式免费行；模型详情页只使用内联 `channelModelPrices` 参与免费判断，除非后续能拿到足够上下文确认该模型确实属于隐式免费。

## 缓存与 DOM 筛选

模型详情页响应会被缓存到内存中的 `modelProviderPriceCache`：

```text
channelID:modelID -> true | false
```

脚本替换页面中的“创建 API 密钥”按钮时，会把渠道 ID 和名称写入按钮的 `dataset`。当用户切换价格筛选时：

1. 从按钮上下文找到渠道。
2. 使用 `channelID:modelID` 查询缓存。
3. 给渠道卡片上下文写入：

```html
data-hub-tool-price-hidden="true"
```

CSS 负责隐藏：

```css
[data-hub-tool-price-hidden="true"] {
  display: none !important;
}
```

## 已知边界

- Channel Hub 无搜索词免费筛选依赖 `priceSummary.allFree`。如果接口缺失该字段，脚本不会猜测免费状态。
- Channel Hub 有搜索词时，接口不携带 `channelModelPrices`；对 `priceSummary.hasPrices === true` 的渠道需要补拉 `ChannelModelPrices` 才能判断搜索命中的具体模型是否免费。
- Channel Hub 分页总数是脚本根据已扫描结果构造的近似值，不等价于后端完整统计。
- 模型详情页必须拿到 `pricing.flatFee` 才能正确识别固定费用；脚本已对 `MarketplaceModel` query 做字段补充。
- 隐式免费价格行是脚本侧展示补丁，只应用于已通过搜索上下文确认的模型，不代表后端真实存在该价格行。
- 抓包文档中的 `authorization` 和 `cookie` 均为脱敏或空值，不应写入真实凭证。
